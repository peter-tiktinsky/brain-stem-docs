Context & memory · rationale

Governed memory and project context

Baseline Claude Code persists instructions and auto memory, but persistence does not govern duplication, contradiction, scope, staleness, or the larger body of project knowledge stored elsewhere. As those surfaces grow, startup context can bloat while the information needed for a task remains hard to find. Brain Stem keeps operational memory typed, bounded, and maintained, then routes from one concise gateway into plans, research, decisions, handoffs, references, and outputs on demand.

Context & memory

Dual context layers

Route project context through a small, navigable gateway. Context is the larger system: the durable material that frames the work, records its state, and lets a session retrieve the right detail without loading the whole project. It is distinct from operational memory, which governs what the assistant should retain or how it should act. Brain Stem splits research across a project Workshop and durable project record, a universal Library of reusable reference, and a promotion path between them; the load-bearing thread is that derived surfaces can stay current while hand-maintained summaries rot. The rows below are the ones that belong to context & memory; the binder, _situating.md, and launch-directory identity are addressed in the project management rationale, and the work/ deliverable layer in the work-folder guidebook.

The memory model

Curate memory without overloading startup context. Each Claude Code session begins with a fresh context window, but it does not begin without durable knowledge: native instructions and auto memory load at startup, and local transcripts can be resumed. Brain Stem's memory pillar governs what should survive and how it relates to the larger context graph. On top of the native loading shape it adds an explicit taxonomy, scope model, guards, promotion paths, and housekeeping that can flag or reconcile structural bloat, overlap, and conflict. It does not silently treat every observation as equally authoritative or automatically delete judgment-sensitive material.

Brain Stem choseoverbecauseground
Split durable memory into exactly three kinds — semantic, procedural, episodic One undifferentiated pile A single bucket gives a stale one-time correction the same retrieval weight as a durable fact. The split is the fifty-year memory-science consensus — episodic/semantic Tulving 1972, declarative/procedural Cohen & Squire 1980 — carried onto agents CoALA MemGPT. A fourth "reflective" type was rejected: reflection is a process, and its output is already a fact or a rule. convergence
A small, curated memory A catch-everything store of every observation The more a catch-all grows, the lower its signal-to-noise falls. Mirrors MemGPT's small-core principle MemGPT; Brain Stem asserts no measured decay rate, only the qualitative trend. convergence
Two governed scopes — project memory plus universal instructions and rules Mixing project-specific and universal material in one shared memory corpus Claude Code keys auto memory per repository by default and also supports configurable memory locations; user-level CLAUDE.md and rules load across projects CC memory. Brain Stem chooses an explicit project/universal split so local observations do not silently acquire global authority. constraint
Declare each note's kind at write time A separate program guessing the kind afterward The author already knows the fact's kind and can state it; guessing introduces silent misclassification you'd have to second-guess. The taxonomy is frozen at five filename prefixes times three retrieval types. convergence
Automated promotion writes only to rules/ Letting any writer touch your CLAUDE.md Your personal CLAUDE.md is authored once and yours alone to hand-edit — survivorship. Trust differs by direction: promoting project lessons up proposes-then-confirms; pulling from an external store is never automatic. convergence
Episodic capture = a no-LLM chronicle plus one index pointer A per-session CoALA-STAR narrative CoALA A per-session STAR narrative would be static boilerplate with no retrieval value and would compete with the optional recall plugin. "Auto-generated survives, hand-maintained rots," so capture is harvested, not authored — a two-stage shape Zep LangMem independently endorse. convergence
Rotate the chronicle at a ~50 KB cap Calling 50 KB a "measured threshold" A no-LLM session-end hook can't tokenize, so bytes proxy a single-read token budget (retrieval-budget figures mem0) context engineering Lost in the Middle; the cap is a deliberate proxy, not a measured threshold. convergence local parameter
Keep the live Brain Stem memory corpus project-scoped One shared corpus, a hybrid, or tiering only by access frequency The bounded startup index makes a single growing corpus increasingly selective. Project scope matches Claude Code's native repository boundary by default, prevents unrelated work from competing for the same hot index, and leaves genuinely universal guidance in its own small tier #21858/#25562. convergence

What loads each session

The load boundary itself is a design decision. The native auto-memory entrypoint is bounded to the first 200 lines or 25 KB; detail belongs in topic files read on demand CC memory. Brain Stem adopts that efficient loading shape: generated binder indexes and the situating card turn the project's assets into a navigable project knowledge graph, and Claude automatically loads the small situating gateway, not the entire corpus, following its pointers only when the current task needs more. The rows below govern that boundary — the bounded gateway, the checks that keep the loaded index small and honest, and where the harness actually reads it.

Brain Stem choseoverbecauseground
Use Claude Code's small auto-loaded index plus fetch-on-demand detail as the memory gateway A second unbounded or fully auto-loaded memory store Claude Code already loads a bounded MEMORY.md and reads topic files on demand CC memory. Brain Stem builds on that native shape instead of duplicating it, while governing what the index points to and how its entries connect to project context. constraint
Resolve the memory directory exactly as the harness does Reconstructing the slug with a naive path-replace Several near-misses would write where the running session never reads. The resolver must match the shipped binary — key by git root, realpath, honor autoMemoryDirectory first CC memory. constraint
Supplement the native post-write size check with an advisory Brain Stem guard Blocking the save, or assuming native size maintenance governs the wider context layer Claude Code already measures MEMORY.md after a write and asks Claude to shorten it near or beyond the load limit. Brain Stem's guard adds earlier, policy-level visibility across its own curated memory surfaces without blocking or auto-deleting them. Over-blocking a legitimate save trains people to disable the guard OPA Gatekeeper ESLint. convergence
Count both raw and comment-stripped lines; gate on the larger A naive single-direction size check Otherwise bulky content could hide inside HTML comments to dodge the check — yet still cost load budget. Comment-stripping is not documented for MEMORY.md CC CLAUDE.md, so the safe default assumes comments cost budget. convergence
Keep a fixed section order and make overflow volume-gated A calendar trigger or an order that changes between writes The Semantic→Procedural→Episodic order makes the cold boundary knowable from the index. The trigger follows actual pressure on the bounded index rather than an arbitrary rule such as "wait 30 days." convergence
Carry a machine-readable presence map alongside the human render Keeping only the inline render, or only the map Inline-only forces machines to parse rendered prose Tolerant Reader; map-only loses the human "checked-and-absent vs broken-link" disambiguation. Serve both audiences without coupling them. convergence
