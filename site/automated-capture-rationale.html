Automated capture · rationale

Bringing outside information into the graph

Baseline Claude Code can transport or trigger outside information, but it does not prescribe how many automated sources should share destinations, preserve provenance, resolve collisions, or avoid unnecessary model cost. Without that ingestion architecture, capture can create silos, overwrite edits, or spend tokens on deterministic work. Brain Stem supplies one governed route into the graph: registered writers, deterministic processing by default, isolated model judgment, and replayable provenance.

Decision rationale · citations resolve to the central source register. General write-time controls are covered under governance.

Automated capture

The vault-writer system

Route outside information safely and efficiently. The graph is shared by human, assistant, and automated writers. Left uncoordinated, captured material becomes a second pile: two writes race, logs pollute reference, regenerations clobber edits, and outputs arrive without the metadata or placement that make them retrievable later. The writer pipeline connects ingestion to Brain Stem's governance model. Its single-writer staged lane is a deliberate solution for contended destinations, supported by convergent practice—not the only architecture Claude Code could host.

The pipeline's default posture is deterministic: mechanical direct-write, no model in the loop. The LLM reasoning lane is an opt-in addition for the judgment calls that determinism cannot handle — not the default path, and not the writer. This limits unnecessary token use and keeps repeated imports reproducible. That distinction runs through every row below.

Ship the substrate, and leave the connectors to you Shipping ready-made connectors for particular sources Claude Code already carries the transports — MCP servers, channels, hooks, scheduled tasks. What it leaves open is the destination: who may write where, with what provenance, and who wins a collision. Brain Stem ships that part — writer registration, the staging packet, the writer-reconciler, the manifest — and a connector stays a script you own, so its source, its credentials and its routing stay yours. The source names in a registration are labels, not shipped code. constraint
One reconciler as the sole writer of every staged file Every writer writing the destination directly Two saves can overlap and silently clobber each other with no record. The platform ships no shared-write coordinator for custom connectors; Brain Stem chooses a single-writer funnel for destinations that opt into staging. Funneling through one program is independently the Single Writer Principle, enforced by a real batch lock lockf. convergence
Direct write by default; the staging pipeline opt-in per destination Staged packets everywhere, or direct-write only Staging everywhere taxes the common single-writer case for no benefit; direct-only can't protect genuinely contended files. Per-destination opt-in pays the cost only where contention or survivorship is real. convergence
Content-hash-named packets, written by atomic rename Hand-composed packets written in place Naming by content hash gives free deduplication; atomic temp-then-rename means no reader ever sees a half-written file. This is content-addressable storage plus POSIX atomic rename — Git's object model CAS + rename(2). convergence
A file-watch trigger plus a relaxed timer backstop Pure timer-poll, or pure event-watch Blind polling adds minutes of latency; pure event-watch loses a dropped event forever. macOS launchd expresses both in one job launchd — seconds-level response plus insurance. convergence
Deterministic processing by default; a model only where you opt in Running every capture through a model A fixed transform gives the same result on every run, so a repeated import is reproducible and the same fact arriving twice collapses the same way; a model's phrasing drifts, and every call spends tokens, a finite resource context engineering. The shipped path is mechanical end to end. The model lane runs through headless mode only for a writer you register with a prompt-guided strategy; out of the box it composes nothing. constraint convergence
The AI merge lane never writes the destination — it emits a packet back to staging Letting the smartest lane be the final writer of record The optional doc-amender runs content through the model headless mode but drops a new packet back into staging, so the one mechanical reconciler still performs the final write — keeping a single accountable chokepoint. Conflicts are block-and-log, never silent overwrite. convergence

A later change of mind — a second source, a dashboard — then builds on data already kept instead of re-extracting it from prose.
