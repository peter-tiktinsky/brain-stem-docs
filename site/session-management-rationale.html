Session management · rationale

Coordinating work across sessions

Baseline Claude Code can resume, compact, isolate, inspect, and connect sessions, but it does not automatically orient each one to current project state, declare shared work, preserve a structured semantic checkpoint, or reconcile project knowledge at close. The resulting manual ceremony matters most when work overlaps or the context window is under pressure. Brain Stem automates that continuity: enrolled sessions start situated, expose relevant collisions, save state, and prepare the graph for the next session.

Sessions

Maintain continuity and coordination automatically. A session is a saved, resumable conversation, but its active working context is still perishable. When a long session approaches its window, the platform compacts it: verbatim conversation in the active context is replaced by a summary, while the local transcript remains available as session data CC context-window. Claude Code also re-injects several native surfaces after compaction. Brain Stem protects a different layer: the exact project state a future turn or fresh session must act on, and the derived project context that should be refreshed when the session closes.

Multi-session coordination

Brain Stem's registry and activity views let enrolled sessions sequence overlapping work through shared state and warnings; direct messaging is useful, but not required for every routine coordination event.

Brain Stem choseoverbecauseground
Add declared-work and shared-file coordination through a machine-local Brain Stem registry Assuming native session discovery or messaging alone prevents file collisions, or syncing locks across machines Claude Code can detect running sessions and supports cross-session messaging, while worktrees provide stronger filesystem isolation. Brain Stem's registry adds project enrollment, declared paths, and same-file warnings for sessions that intentionally share a checkout. The lock and liveness checks are physically local and mean nothing on another machine Kleppmann; a hot synced file also invites conflict-copies. So coordination stays local, written atomically, serialized with a lock lockf. convergence

The close decisions: run the cleanup chain without wedging the session, and record what happened without polluting the indexed graph.

Decision quality

The decision-quality protocol

Research consequential choices before asking. The decision-quality protocol addresses a failure mode distinct from the session-continuity problems above. When Claude Code presents consequential options—scope, approach, design, sequencing—there is a recurring risk that it rationalizes the first option set it surfaces rather than expanding the space. This is not a missing native tool or a context-window problem; it is a deliberate-reasoning policy. The protocol adds a structured research pass before options are published to the user.

Deep dive: the mechanics — the pre-asq-guard hook, the substance heuristic, the research_complete: annotation that clears it, and the advisory override — live on the decision-quality protocol page.

The 4-element pass the guard asks for:

1

Re-read the project goals

Read the active plan's spec, manifest, and recent handoff before surfacing options. The right answer is often constrained by criteria already documented.

2

Check inter-project dependencies

Scan adjacent plans for conflicts, synergies, or shared infrastructure that changes the decision shape. An option that looks clean in isolation may block a parallel plan.

3

Read the live vault state

Read current files; do not trust memory. Memories are point-in-time observations; the code on disk is authoritative. Many "debates" dissolve when someone reads the file.

4

Generate one unconsidered option

Produce one option not already on the table. This is the load-bearing step — it expands the option space rather than rationalizing the existing list. Without it, the protocol collapses into performative deliberation.

A substance heuristic on AskUserQuestion that fires before options are published A standing instruction in CLAUDE.md to "always research options first" Standing prose instructions degrade over a handful of sessions and get rationalized away under pressure. A hook fires regardless of whether the model is cooperating — the same constraint that drives the governance engine's write-time interception. Deny the call and hand back the protocol, with an annotation as the way through An additionalContext nudge the model can acknowledge and step past Empirically, a "research each option thoroughly" prompt overrides the model's first-presented options in nearly every session — so the pass is worth insisting on. An advisory does not reliably produce it; a denial does, and it is cheap to clear: run the pass, re-issue the same question with a one-line research_complete: summary. The advisory form stays available behind an environment setting for anyone who wants the softer shape. convergence
The +1 unconsidered-option step as the mandatory fourth element A simpler "re-read goals + read files" two-step Re-reading existing material rationalizes; generating one new option expands. Tree-of-Thought and Reflexion research demonstrate that deliberate divergence from the initial hypothesis is the mechanism that produces better answers — not reviewing the same set more carefully. The step is structural, not stylistic. convergence
One coded skip-condition — the yes/no shape: exactly two options whose labels are both plain answers (yes, no, cancel, skip and their kin) Firing the protocol on every AskUserQuestion call Alert fatigue from a gate that fires on "ready to proceed?" would train users to work around it. The yes/no skip follows the same data-gated principle that governs how governance rules earn the right to get strict. The exact accepted-answer vocabulary is a local parameter; everything else is excluded only incidentally, by carrying neither a scope keyword nor an option description long enough to read as substantive. convergence local parameter
Denial as the shipped default, with the advisory form available as an environment opt-in Shipping advisory-only, or deferring the entire protocol The denial earned the default by clearing a telemetry gate first: the hook records every fire, and a 52-fire run showed it landing on substantive option sets and not on trivial ones — 45 already annotated, 7 nudged, all 7 genuinely substantive. Telemetry keeps being written on every fire, so the false-positive rate stays visible rather than assumed. convergence local parameter
