Getting started · removing Brain Stem cleanly

Uninstalling

Removing Brain Stem is one command. The important thing to understand first is what it will and will not touch — because the uninstaller is deliberately careful: inside the folders it installed it removes only the untouched files it originally laid down, it copies your install to a backup before it starts, and it leaves your notes alone. The exception is the two top-level configuration files, settings.json and settings.local.json: those are removed by name whether or not you edited them, so your version of them lives in the backup.

For why uninstall behaves this way, see Packaging & runtime.

The command

Run the uninstaller from the Brain Stem project you cloned, pointing it at your install with CLAUDE_HOME:

CLAUDE_HOME=~/.claude bash uninstall.sh

That is the whole operation. There is no separate confirmation flag to learn. The uninstaller is not copied into your install — it stays in the project repo — and it refuses to run unless CLAUDE_HOME tells it which install to remove. What happens next is described below so there are no surprises.

What it does, step by step

1 · Verifyconfirm this is really a Brain Stem install, via the provenance log
›
2 · Back upcopy the install folder, minus session transcripts, to a timestamped backup first
›
3 · Stop jobsstop only background jobs in the com.brain-stem name-space
›
4 · Removefile by file — remove untouched originals, keep files you edited in the installed folders
  1. It checks that this is really a Brain Stem install. The installer left a dated record (a provenance log) in ~/.claude/logs/ proving an install happened and naming the folder it wrote to. The uninstaller reads that record and confirms the folder you are removing matches. If there is no install record, it refuses — you should not "reverse" an install that was never made.
  2. It backs your install up first. Before removing a single file, it copies the install folder into a timestamped backup named .pre-uninstall-<timestamp>/. Three things stay out of that copy: the source repository's .git history, the projects/ folder of Claude Code session transcripts (they can contain credentials you pasted into a session, and there is no way to redact them), and any earlier .pre-uninstall-* backup. Everything else is the safety net: an unexpected outcome is recoverable from that copy.
  3. It stops Brain Stem's background jobs — and only those. Every scheduled job Brain Stem creates is named starting with com.brain-stem. The uninstaller stops and removes only jobs in that reserved name-space. If it ever finds a job whose name merely looks similar but sits outside that prefix, it aborts rather than risk stopping something unrelated (your backup stays intact).
  4. Inside the installed folders, it removes files one at a time, checking each. For every file the install originally laid down there, the uninstaller re-computes that file's fingerprint (a signature of its exact contents) and compares it to the receipt recorded at install time:
    • Unchanged — exactly as Brain Stem shipped it, in this release or an earlier one → it is removed.
    • Edited by you — the contents match no version Brain Stem ever shipped → it is kept, unless you pass --force-rm-edited.
    So your personal edits inside those folders survive by default. Two things sit outside this per-file check and are removed outright: the top-level settings.json and settings.local.json, and Brain Stem's own bookkeeping under governance/ — the installed-file receipts, the governance action log, the install-state records and the project registry.

What is preserved

Kept

Your vault & your edits

Your notes folder is yours; uninstall does not delete it. And a shipped file you changed inside the installed folders is left in place, named on screen as it is preserved. The top-level settings.json and settings.local.json are the exception — they are removed by name, so take your version back out of the backup.

Kept

Your working data & the record

Accumulated working data lives apart from the program — durable data under ~/.local/share/brain-stem, disposable state under ~/.local/state/brain-stem — so removing the program does not endanger it. The ~/.claude/logs/ provenance log is kept too, so there is always a trail of what happened.

The project registry is part of the install — so it is removed

Brain Stem keeps a small registry of the projects (spokes) you have registered. Unlike your notes and your own edits, that registry is Brain Stem's own state, not content you authored — it lives inside the install, so a full uninstall removes it along with everything else Brain Stem laid down. (An upgrade does the opposite and preserves it.) If you reinstall later you start with the shipped starter registry — two entries: the fallback identity for a folder you have not registered, and Brain Stem's own workspace — and re-register your projects. The projects themselves, on disk under ~/work/, are never touched.

Good to know

There is no dry-run / preview for uninstall

Unlike the installer — whose default is a write-free preview — the uninstaller does not show you a plan first. The mandatory backup taken in step 2 is the safety mechanism instead. Expect it to copy your install aside, not to rehearse.

  • If something looks wrong afterward, everything the uninstaller removed from your install folder is in the .pre-uninstall-<timestamp>/ backup folder it made before starting. The one thing not copied there is the scheduled-job definitions it removes from ~/Library/LaunchAgents — reinstalling writes those again.
  • Reinstalling later is the same first-time path as before: clone, preview, --apply. See the Install & upgrade guide.
