Commands

A command here is a slash command: you type a slash and a name into a running Claude Code session and it runs a packaged capability called a skill. These are the nine commands Brain Stem adds for you to run directly — grouped below by the part of the system they belong to. In practice you will type few of them: Claude Code invokes the right skill by itself when what you ask matches what it does — the final section shows exactly which run on their own.

Each entry: the one thing it does, when you'd reach for it, and a link into the section that explains the why.

Getting started

/onboard

The one-time guided setup that personalizes everything. It runs a short two-part interview — a confirmation card of facts it already looked up (name, email, timezone, a proposed vault location), then a few questions in your own words — and from your answers writes a settings file (user-manifest.json), your personal ~/.claude/CLAUDE.md preferences file, and a freshly built vault. It also records whether you want a couple of optional external integrations. It is safe to run more than once; it will not clobber what it already wrote.

Project management

These four commands support running multi-step projects. They are only relevant if you use Brain Stem's plans workflow; you can ignore them otherwise.

/new-plan

Scaffolds a complete, rule-compliant plan directory in a single step — the standard set of files a plan needs (spec.md, tasks.md, handoff.md, manifest.json, plus a placeholder idea brief) — assigning the next available number prefix and rejecting low-information folder names. A --master mode scaffolds a larger multi-phase plan. Use it when you want a plan set up cleanly without the research-first route below.

/backlog-triage

Captures a raw, pre-plan idea into your idea inbox and automatically classifies it as new, a duplicate, an overlap with something existing, or deferred — so the backlog does not accumulate near-identical entries. Use it the moment an idea occurs to you.

/backlog-research

Does deep research on a triaged idea (or an in-flight plan): it reads your vault, your setup, and outside best practices, then writes an ideation brief and a draft plan directory. A --promote flag graduates a captured idea straight into a plan. Use it when an idea is promising enough to be worth investigating before committing to it.

/backlog-hygiene

A review loop over the whole backlog. It scans your idea inbox and your in-flight plans for staleness and for items missing a decision about what happens next, and with --fix applies one safe automatic repair — flagging the items that still need a call. It never archives or moves rows: tucking finished plans out of sight is a display-only filter in the rendered index, not something hygiene does to your data. Use it periodically to keep the backlog honest.

Session management

/session-checkpoint

Writes a save-point of the current conversation — what you are working on, what is done, what is next — in a fixed structure, so a long session can survive its working memory being trimmed (which Claude Code does automatically when a conversation gets long). It is also fired automatically as a session fills up; you can run it yourself before a long task or when you want a clean handoff.

/librarian

The vault, plan, and governance maintenance entry point. It audits and reconciles the governance rules, plan status, and the vault's auto-generated index files, and regenerates derived files (tables of contents, task lists, rule indexes) so they cannot drift out of date. End-of-session reconciliation is one of its modes — which is where you will reach for it most: to tidy up at the close of a working session.

It is one skill with a catalog of 58 named capabilities beneath it. Any one can be run directly — /librarian inbox-settle — and /librarian full sweeps the whole audit set. Much of the catalog also runs itself: a fixed chain reconciles at every session close, and a scheduled subset re-fires on its own cadence. The catalog, broken down by focus area:

Mode: audit — checks and reports, changes nothing · audit + fix — checks, and carries the coded repair behind an explicit flag or a dry-run review · maintain — rewrites a generated surface from its source of truth · asks first — judgment work: proposes the change and waits for your go-ahead before writing anything.

When it runs by itself: full — in every full audit sweep · daily / weekly — runs itself at session close once that much time has passed (closes are the clock; there is no background scheduler) · close — in the automatic session-close chain, every close · live — needs you and a running session, not a detached run · delegated — run by another capability as part of its job · by name — no automatic run at all.

And on demand — always. The When column describes only the automatic layer. Every capability in this catalog — including every full item — also runs the moment it is asked for. Type /librarian <name> yourself, or simply ask for the work — settle this inbox idea, repair the links in my vault, why is my context so big — and Claude Code invokes the librarian skill with the right capability on its own. The full sweep is the audit ritual; ordinary work is the more common trigger.

Context & memory

/mem-promote

Proposes moving observations from the optional claude-mem plugin (which auto-captures notes about your sessions) into your curated, hand-trusted file memory. It gathers candidates, reshapes them, checks for conflicts, and then asks before writing — it never writes memory automatically. This command is only useful if you have installed claude-mem.

System personalization

/govern register

The sanctioned way to extend the rules to cover something the foundation does not yet know about — without editing (and without forking) the shipped rule files. Each registration lands in your personal overlay, which sits on top of the foundation. You type it directly; it is never run automatically on your behalf. It has six kinds, named with --kind:

--kindRegistersExample
folderA new top-level folder in your vault, with its own conventionsA new Clients/ area
file-typeA new kind of file (its required shape) within an existing folderA meeting-note type
tag-extensionA new tag dimension prefix, alongside the ones the foundation declaresA client/ dimension
writerA new automated system that writes into your vault, so it is catalogued and governedA scheduled importer
doc-amender-promptThe instructions used when an automated edit needs the assistant to reconcile a fileCustom merge guidance
projectA ~/work/<spoke> project workspace, plus a vault-view routing rule so it surfaces in your vaultA new client engagement workspace
 
/govern register --kind folder --target <vault-relative-path> [--inherit-from <parent-path>]

Invoked for you — what runs without typing

You do not have to memorize this page

Claude Code reads the description of every shipped skill and invokes the right one by itself the moment what you ask for matches what it does — so most, if not all, of the commands above will simply happen inside the work you ask for. Ask for a new multi-step project and the new-plan skill scaffolds it; mention a raw idea and backlog-triage captures it; ask where your context is going and the librarian measures it. The slash commands exist for the moments you want to call one deliberately — not as a vocabulary to learn.

Two are typed-only by design: /onboard and /govern register. First-time setup and extending the rulebook are governance acts you perform consciously, so the skills that do them cannot be pulled in mid-conversation. When a request touches that seam — say, a new kind of work folder the rules do not yet cover — Claude will not improvise its own conventions: the standing rules and write-time advisories point at /govern register as the sanctioned route, and it will tell you so.
