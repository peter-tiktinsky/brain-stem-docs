System personalization · what your system runs

The System Map

A system built on Brain Stem grows hooks, librarian capabilities, skills and scheduled jobs, and nothing shows them together. /librarian system-map reads your installed home and writes one short page for each, plus an index, so “what does my system run?” becomes a folder you can open.

A capability, skill or hook of your own appears on the next render. To build one, see Build your own capabilities.

What it maps

MemberRead from
HookEach distinct event, matcher and command in the hooks section of settings.json
CapabilityEach entry of the capability registry of every skill, the shipped librarian’s and every capability root of your own
SkillEach skill folder that holds a SKILL.md
JobEach scheduled job, whether it is still a template or already rendered. A template and its rendered file count as one job

What a page holds

Each page is six lines, with no date, host or user name: a title, the trigger, what it reads or writes, its lane, its script and its source. The pages sit in four folders, hook/, capability/, skill/ and job/, beside an index page that counts each kind.

The command

system-map.sh [--render | --check | --dry-run] [--out DIR]
ModeWhat it does
--renderWrites the pages, the index and a marker file under the output root, and removes the pages of members you have since deleted
--check (the default)Writes nothing. Exits 0 with system-map: ok when every page is current, or exits 1 and names the first page that has gone stale
--dry-runWrites nothing and prints how many pages and members there are

The output root is --out, else the SYSTEM_MAP_OUT setting, else a system-map folder in your state directory. The command rewrites a root only when it carries its own marker file; it refuses a non-empty folder that does not, and never touches it. A refusal exits 2 with one line and changes nothing.
