System personalization · rationale

Extending Brain Stem without lock-in

Baseline Claude Code offers many extension surfaces, but assembling them into a coherent, upgrade-safe system—and preserving ownership across setup, customization, upgrade, and uninstall—remains the adopter's responsibility. That gap can fragment policy, clobber local work, or lock knowledge to one tool. Brain Stem supplies governed extension seams and an ownership-aware package lifecycle while keeping the graph in portable plain files that other models and retrieval tools can use.

Governance personalization

Separate the foundation from your extensions. These three rows are the personalization half of the governance pillar — how you extend or override the shipped rules without ever editing the foundation. The core write-time doorman decisions (pre-write hook, three verdicts, advise-by-default, data-gated strictness) live on write-time governance rationale. What sits here is the seam Brain Stem opens for you to reshape governance to your situation: a sealed shipped base you never touch, a transparent overlay you own, and one guided command (/govern register) that covers all 6 extension modes — 5 governable-asset kinds (folder, file-type, tag-extension, writer, doc-amender-prompt) plus the project work-spoke on-ramp.

Brain Stem choseoverbecauseground
A sealed master plus a transparent overlay One rulebook everyone hand-edits Your additions go in a separate overlay deep-merged on top; the shipped master is never edited locally. This is the structural guarantee behind taking an upgrade without losing your customizations Kustomize git config CSS cascade. convergence
An override must carry a mandatory free-text _override_reason Letting the local rule win silently Because the overlay wins on a collision, a silent override could shadow a shipped rule unnoticed. Brain Stem blocks the merge unless the entry carries an _override_reason — deliberately stricter than its own analogs git config Kustomize, matching policy-as-code waiver practice waiver practice OPA bundles. Extend (new keys only) is frictionless and needs no reason; only a collision triggers the requirement. A per-write --force-override flag exists for non-persistent cases. convergence
One sanctioned extension path — /govern register Hand-editing the overlay file directly The skill walks a propose-then-confirm conversation, validates each field, and appends to an audit log; hand-editing bypasses both. The skill covers all 6 modes: registering a folder type, a file-type contract, a tag extension, a writer, a doc-amender prompt, or a project work-spoke. The hook only proposes (and lets you skip); a human runs the skill CC skills wizard UX. convergence

Knowledge-graph extendability

Keep the knowledge graph portable. Personalization extends beyond changing Brain Stem's own rules. The context layer is ordinary Markdown, YAML, JSON, relative links, stable identities, generated indexes, and published schemas. Those choices let a custom skill inherit Brain Stem's routing and maintenance, and let a second harness, local model, vector index, or relationship graph read the corpus without reverse-engineering it. The graph is already organized into stable, efficiently chunkable, metadata-rich material; an external retrieval system can build on that substrate instead of first repairing an unstructured archive. Brain Stem ships the substrate and blueprint—not a search server or graph database.

Brain Stem choseoverbecauseground
Model-agnostic plain files plus machine-readable structural blueprints An application-owned or opaque knowledge store Typed frontmatter, stable IDs, relative links, heading boundaries, indexes, schemas, and governance registries let another reader navigate the same corpus without depending on Obsidian or Claude Code. convergence
Read-only external consumption by default Assuming every outside harness is a safe writer Brain Stem's immediate write-time governance lives in Claude Code hooks. An external index or model can safely read the graph; an external writer bypasses those gates unless it implements equivalent contracts and reconciliation. constraint
Ship the retrieval-ready substrate, not a mandatory vector or graph service Binding the foundation to one search engine, embedding model, or server The corpus already exposes deterministic chunk boundaries, metadata filters, stable identity, and one root to walk. An adopter can add semantic retrieval or a relationship database when its value exceeds its operational cost, without rebuilding the source corpus. convergence

Onboarding

Personalize once at a governed seam. Onboarding is the one-time guided interview you run when you first type /onboard. It asks who you are and how you work, then writes your global preferences file and builds your starter vault — the seam where the identical install everyone downloads becomes your system. The split here is clean: the shape of a good first-run flow (smart-default pre-fill, run-once, validate-before-write, never clobber) is convergent setup-wizard practice; some mechanics—such as preventing model invocation of the onboarding skill—follow documented platform controls. Together those constraints and practices produce the flow below. One scope rule governs everything on this page — Brain Stem ships only the minimum-viable seed.

Brain Stem choseoverbecauseground
A one-time guided interview as the personalization seam The same generic install for everyone, or hand-edited config per machine You don't assemble a toolkit; you move into a furnished foundation and personalize it at one known seam. The mechanism matches established setup-wizard practice wizard UX. convergence
The assistant can never start onboarding on its own Default skill behavior, where the model can decide to fire a skill Onboarding writes your personal files and builds your vault — it must never surprise you by running unprompted mid-task. The guard rests on a documented platform setting CC skills; only a human typing /onboard launches it. constraint
Run once, then no-op; redoing it takes an explicit --force Letting setup re-run freely, or self-deleting after a successful run A step that writes irreplaceable personal content must never be cheap to repeat by accident; self-deletion mid-run is racy and breaks the resume path. convergence
A two-part interview — a pre-filled confirmation card, then short optional prose Making you type the mechanical facts, or a long interrogative wizard Section A is fact-gathering a probe can do (name/email from git config, timezone from the clock); Section B is the genuinely human input — how you work — that no probe can guess, and it is fully optional. convergence
One AI step — a two-pass extraction of your prose into labeled fields Pure deterministic capture of the raw answer Verbose conversational answers must be consolidated to fit the preferences file's size cap (~four lines per block in a ~60-line file). The structural check confirms the summary lands in the right slots. constraint convergence
Validate first, write atomically — block-and-log, never write-and-hope Writing optimistically and hoping it completes The manifest is schema-checked and both preferences files are scanned for leftover placeholders before anything is written; writes go to a temp file then swap; on any failure it stops and reports, leaving no half-written file. convergence
Author the two CLAUDE.md files fresh; ship no pre-seeded placeholder Shipping a pre-seeded placeholder preferences file in the install A file full of unfilled tokens looks broken to a reader and blocks the genuine first-run fill — getting no file is cleaner than a broken one. The global file loads first, then the more specific one, rather than one silently overriding another CC CLAUDE.md. convergence
A re-run never silently overwrites a file you edited Silently overwriting on re-run If a CLAUDE.md differs from a fresh render, onboarding writes a .new file and shows you the diff, leaving the real file untouched until you decide — your edits are sacred, the same preserve-don't-clobber pattern as chezmoi. convergence
End with shortcuts and an explicit "open it in Obsidian" instruction Silently trailing off once the folder is built Building the folder is invisible; the adopter needs an explicit, concrete next action. The hand-off "hands you the key and tells you which drawer to open first." convergence
Treat external tools as a soft mandate — probe, recommend, frictionless skip A hard requirement that blocks setup For each optional add-on: a read-only presence probe, then a strong recommendation, the honest reason, the exact command, and a clean "skip and do it later." It records your choice and never blocks wizard UX. convergence

Packaging & runtime

Protect ownership through the package lifecycle. Claude Code has explicit configuration scopes and a plugin system, but a multi-file personal foundation still needs to distinguish shipped assets from adopter edits, reconcile existing settings, preserve customizations through upgrades, and remove only what it owns. Brain Stem's packaging discipline closes that package-lifecycle gap. Its choices converge with Homebrew, dpkg, chezmoi, Flyway, rustup, and the XDG spec, then add a provably write-free plan before the first write.

Brain Stem choseoverbecauseground
A preview-first install — install.sh writes zero files without --apply An installer that writes immediately It runs every check, prints a machine-readable plan of every operation, and exits; writing must be asked for by name. The safe thing is the default, the consequential thing asked for — the check-then-apply gate rustup uses. convergence
Refuse an apply when CLAUDE_HOME is unset; let a dry-run assume it Treating preview and apply symmetrically A preview may assume a target to render a plausible plan; a real write may not. Real files only ever land in a folder you deliberately pointed them at. convergence
A generated, fingerprinted receipt of every shipped file A hand-maintained ship-list A hand list always drifts, and a receipt that lies is worse than none. The manifest generator walks the same source surface the installer ships, and a release-time completeness check holds the two enumerations in step — exactly how Homebrew / Nix / apt-dpkg know what they put down. convergence
An edit-preserving uninstall (fingerprint match — remove; mismatch — keep) A blunt rm -rf of the folder Over time your files live right next to the foundation's, so a blunt delete takes your customizations with it. The manifest is the boundary between managed and unmanaged — preserving changed files is what chezmoi does. convergence
Distinguish drift from tamper on upgrade via per-release baselines A blind copy (clobbers edits) or a blind skip (fails to deliver fixes) A file matching a recorded shipped baseline is managed drift — install the current version; a file matching no shipped baseline is your edit — install the current version too, but snapshot your edited bytes aside as .foundation-local. The sidecar is dpkg's .dpkg-old; the version-keyed baselines are Flyway/Alembic's high-water-mark. convergence
All-or-nothing writes via a per-file rollback journal The Capistrano whole-tree symlink swap, or a recursive subtree copy You can't atomically swap a directory that holds the user's live, interleaved state Capistrano, and cp -R can't honor per-file rename atomicity — so the work is decomposed to a per-file walk with a reverse-replayable journal. constraint
A delivery gate — a half-install is never recorded as success Writing the completion stamp regardless, or a blanket "every file equals shipped" check A blanket check is unsound — it false-refuses the merged overlay and every edited-and-preserved file. The gate checks only that files meant to update did; if not it exits code 56, stamps nothing, and a re-run converges. A short recoverable failure beats a silent incomplete "success." convergence
Merge Brain Stem settings with adopter values preserved, behind a deletion gate A wholesale overwrite, or per-hook hand-patches The merge refuses to proceed if it would silently drop any existing key; a reconciler adds missing foundation hooks without reordering adopter hooks. Claude Code resolves settings across managed, command-line, project-local, project, and user scopes by documented precedence, while list-valued keys generally combine CC settings. Brain Stem's deletion gate is additional package safety, not native merge behavior. convergence
Keep runtime data outside ~/.claude, split durable vs. ephemeral Keeping working state inside the program folder Separating the installed program from the data it generates means uninstalling or reinstalling never endangers your accumulated work — the XDG durable/ephemeral split the foundation already follows. convergence
Keep coordination state machine-local, not in the synced vault Homing the session registry and locks in the synced Obsidian vault A small, hot, frequently-rewritten JSON plus locks in a synced folder is worst-case input — and the cross-machine guarantee is a phantom, since kill -0 and lockf are local-machine constructs Kleppmann. tmux, systemd, git's index.lock, and even Syncthing keep runtime state local runtime-state precedent. convergence
Fence background jobs to the com.brain-stem.* label namespace A careless cleanup that stops unrelated jobs On uninstall it stops only jobs in its reserved prefix and actively refuses to touch an impersonator, aborting rather than risk stopping something unrelated. Reverse-domain naming is the OS-level launchd convention. convergence
